# v1 交付 Goal 提示词

更新日期：2026-08-28。

用途：记录用户要求调整后的完整 Goal 文本，供复制到应用的 Goal 编辑入口。本文件只记录执行指令，不替代规范文档或 AGENTS.md 的权威职责。当前工具不支持改写 Goal 正文，应用界面操作被安全策略禁止，因此**原生 Goal 正文尚未替换**；后续执行遵循本轮用户补充指令和 AGENT_BRIEF 的当前口径。

---

以 `docs/spec/`（v1.6 基线）为唯一需求与设计权威，把 AI 驱动自动化测试框架实现到 v1 交付状态，并通过全部验收。已有实现从台账和 ROADMAP 恢复，不重复从零搭建。

## 事实源与冲突裁决

- 需求与流程：`product/PRD.md`；路线与 DoD：`product/ROADMAP.md`；术语与 ID：`product/GLOSSARY.md`。
- 机器契约：`architecture/DATA_MODEL.md`（Schema 唯一权威）；结构与依赖规则：`architecture/ARCHITECTURE.md`；操作流程遵守根目录 `AGENTS.md`。
- 文档间冲突按各文档已注明的权威关系裁决，裁决理由写入对应 commit message。不得以实现方便为理由重设计或降低验收标准。

## Step 0：环境自检与恢复

1. 检查 Docker/Compose、uv/Python 3.12、Chromium、GitHub 远程仓库与 Actions 权限、通知渠道 webhook。逐项记录真实结果及证据边界，不把未执行的检查写成通过。
2. 按“当前任务是否实际依赖”分类缺项。只有缺项确实使当前任务或其 DoD 无法执行时才暂停；后续阶段才需要的资源先记入待办，不阻止当前可执行工作。
3. 例如，缺少通知 webhook 不阻塞 Phase 2–6 的开发和验证；按 ROADMAP 5.5，Phase 7 前的执行终态直接在本会话呈现。到 Phase 7 首个要求真实通知的 DoD 时，必须取得真实渠道并验证；不能用 mock、本地接收器或 dispatcher 单测替代真实通知验收。
4. 建立/延续 `AGENT_BRIEF.md` 的当前状态、下一步和待办台账。每个任务完成即更新；跨会话恢复只认台账 + ROADMAP 勾选状态，不重读全部对话。

## 阻塞判断与通知纪律

- **非阻塞项**：不影响当前任务的依赖、正确性、安全边界和 DoD。记录问题、影响范围、首次依赖任务、后续动作与所需用户资源，然后继续当前工作。不要为了未来可能需要的资源提前打断，不反复查询没有变化的缺项。
- **必须暂停项**：当前任务或其 DoD 确实无法推进；遇到明确人工确认点；涉及尚未授权的凭据、权限、安全边界、范围变更或不可逆操作。输出已有证据和具体待决问题，不猜测、不代答、不伪造审批。
- 在本轮任务结束时，一次性汇总非阻塞项、影响和用户需要补充的内容；若持续工作至整个 Goal 完成，则在最终交付报告中汇总已解决事项与剩余不影响验收的备注。不要逐条反复通知同一个未变化事项。
- “延后通知”只调整处理时机，不等于豁免 DoD。待办一旦成为当前任务的真实依赖，就按必须暂停项处理。任何 v1 必须验收项未完成，都不得宣称 Goal 完成。
- 自动续跑或“继续”不等于人工签收；本次调整也不构成对 2.1 契约、M1/M2/M8/M13 或其他明确确认点的接受。

## 执行纪律

- 按 ROADMAP 任务顺序：读任务行与 DoD → 实现 → 真实执行 DoD 验证 → 勾选 + commit。当前任务 DoD 未过，不将其标记完成，不越过依赖进入下一任务。
- `[manual gate]`、`human sign-off` 及 AGENTS.md 中的明确确认点：呈现命令输出、diff、产物或记录后暂停，等待用户明确确认。
- 每个任务一个 conventional commit；每完成一个 Phase push 一次。原有脏工作区和无关改动必须保留。
- 新增或修改的代码注释、文档备注使用中文；标识符、命令、协议字段和必要的原始证据保留原文。
- 发现 spec 缺陷或歧义：按权威关系做最小修订，CHANGELOG 留痕，commit 说明理由。需要用户决定的需求/范围歧义不得自行填充。
- ENVIRONMENT_SETUP 的“已运行”状态必须有真实执行证据。单测 fixture/mock 可以验证单测目标，不能替代真实依赖、端到端流程或外部验收；禁止放宽验收脚本让未完成事项通过。
- accepted 上游、审批、状态与事件严格遵守现有唯一写入者及 reopen 规则。

## 结束边界：全部满足才算完成，达成即停

1. ROADMAP Phase 0–9 全部任务勾选，每个 DoD 可证据复核，含 9.2 UI-led 与 9.3 API-led 两条真实迭代端到端 merged。
2. PRD §7 五条验收标准逐条成立且附证据：命令输出、PR 链接、审批记录等；真实通知验收仍包含在内。
3. 9.5 终验清单执行完毕，产出《v1 验收报告》存入 `docs/spec/status/`，列清证据、非阻塞事项处理结果和必要备注。
4. 达成后立即停止：不启动 Deferred 清单中的任何项，不做超纲优化，不继续跑后续迭代。

## 失败停止规则

- 同一 DoD 连续 3 次验证失败且提不出新假设：停止，输出阻塞报告，包含已试路径、证据和需要用户决策的点。
- 只有用户能提供的资源，仅在成为当前任务实际依赖时暂停索取；此前记入待办，不猜测、不借用其他项目凭据、不降低标准绕过。
- 遇到必须暂停项，在最近的安全任务边界更新台账并交还用户；无进展的新自动续跑不得制造重复提交、重复报告或无意义重试。Goal 的完成/阻塞状态变更仍遵守工具本身的条件。
- 上下文即将耗尽：在最近任务边界收尾，commit + 更新台账，不做半途弃置；恢复后从已记录状态继续。
